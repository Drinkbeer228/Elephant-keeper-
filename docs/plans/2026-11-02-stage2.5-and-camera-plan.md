# Этап 2.5 «Физика опилок, карманы и камера» — план реализации

> **Для исполнителя-агента:** задачи идут по порядку, шаги отмечаются чекбоксами (`- [ ]`). Формат и ограничения — как в `docs/plans/2026-11-02-stage2-plan.md`.
> Прогресс отмечать в `docs/plans/2026-11-02-stage2.5-and-camera-progress.md` (журнал по образцу `2026-11-02-stage2-progress.md`).

**Цель:** убрать спам просыпания опилок с тачки (сыпется только «с горкой» и только на манёврах), вернуть плейтест бота на порог 25 за счёт окна поставки после утреннего ажиотажа, дать киперу поясную сумку с лакомствами (до 3, руки свободны), отвязать камеру от размера экрана: следование за кипером с зумом и мёртвой зоной, изолированный HUD и закадровые маркеры «ГУДОК!»/«🐘 !», плюс ярлык быстрого запуска игры из папки.

**Архитектура:** логика в `src/sim/` (чистые функции над `State`, детерминизм по `seed`), карта и баланс — `src/data/`, отрисовка и камера — `src/game/`, DOM-интерфейс — `src/ui/`. Бот `src/dev/bot.ts` доигрывает смену после задач 1–3 (`tests/playtest.test.ts`).

**Стек:** TypeScript 5.9, Phaser 3.90 (Canvas), Vite, Vitest.

## Общие ограничения

- Проверки: `npm run typecheck`, `npm test`, `npm run build` — зелёные после каждой задачи.
- В `src/sim/` и `src/dev/bot.ts` нет `Math.random`; случайность — через `src/sim/rng.ts`.
- Работающие механики этапов 1–2 не ломаем: тазы, совок, тачка с балансом тюков, рохля, бак с мусоровозом, чек-лист сдачи.
- Тексты и комментарии — по-русски, идентификаторы — по-английски.

## Ключевые решения

1. **Опилки сыплются только «с горкой»**: `BALANCE.barrow.overfill = 0.85` — доля наполненности сыпучим (опилки и солома, каждая от своего максимума `sawdustLoad` / `strawLoad`; тюки не считаются — у них свой механик равновесия). Пока доля ≤ 0.85 — ноль потерь при любой езде.
2. **Просыпание — только от встряски** (`jolt`), по 1 заряду за событие:
   - резкий поворот (смена вектора движения, скалярное произведение направлений < 0.3 — как толчок баланса тюков);
   - пересечение границы вольера (въезд/выезд через проход или ворота);
   - упор в стену/препятствие (переход «ехала → упёрлась», чтобы не спамить при удержании кнопки).
3. **Декали троттлятся**: кучка (`state.litter`) появляется не чаще одной на `BALANCE.barrow.litterEvery = 2` клетки пути (`barrow.trail` копит пройденное с последней кучки). В вольере просыпанное не считается, как и раньше.
4. **Поставка — окно вместо пересборки поддонов.** Сократить рейс с 6 до 4 паллет без потери прихода нельзя без «смешанных» поддонов (модель `Cargo` — один вид на поддон), поэтому выбран второй вариант из постановки: окно сдвигается на **09:15–11:30** (`BALANCE.supply { arriveAt: 75, leaveAt: 210 }`) — после утренних сигналов и уборки. Порог плейтеста возвращается 20 → 25, если бот стабильно принимает борт.
5. **Карманы кипера**: `player.pocketTreats` (старт смены — 1, максимум 3). Набор — у склада фруктов (кормовая), «не занимая рук»; дать лакомство из кармана можно рядом со слонихой, даже когда руки заняты, — снимает стресс и прерывает качание (скука падает до ≤ 45). Похвала «за бак» старше кармана: пока есть заслуженное угощение и фрукты в запасе — показывается она.
6. **Камера всегда за кипером**: `startFollow(keeper, false, 0.12, 0.12)`, мёртвая зона ~180×140, границы — реальные размеры карты (`MAP.w/h * TILE`). Базовый зум ≈ 2.0 (зажат в 1.0–2.2 по размеру окна), колесо мыши плавно меняет зум 1.0–2.5, `Tab`/`Z` — переключение «работа ↔ общий план» (общий план = вся карта видна). `pixelArt: true` сохраняется.
7. **HUD — DOM поверх canvas** (уже зафиксирован относительно экрана); канвас-индикаторы (закадровые маркеры) живут в отдельной сцене `OverlayScene` со своей камерой `zoom = 1`, поэтому их не двигает и не масштабирует зум мира.
8. **Ярлык запуска**: `start-keeper-sim.sh` (cd в папку проекта, если порт занят живым сервером — просто открыть браузер, иначе `npm run dev -- --open`) и `Start keeper sim.desktop` (`Terminal=true`, иконка `icon.png`, сгенерированная из пиксель-арта слонихи скриптом `scripts/make-icon.mjs`).
