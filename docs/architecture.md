# Архитектура

## Слои

```
data (план, баланс) ──► sim (состояние и правила) ──► render (Phaser) / ui (DOM) / audio
                                    ▲
                     ввод: StepInput { move, run, actions[] }
```

Симуляция не знает об отрисовке. Состояние `State` — простой JSON без ссылок, `undefined` и `Infinity`, поэтому сохранение побитово точное, а продолжение после загрузки совпадает с продолжением без неё. Все случайности — из генератора, хранимого в состоянии.

Шаг фиксирован: 1/30 секунды симуляции; игровое время идёт со скоростью 1 мин/с днём и 2.5 мин/с ночью, ускорение 2×/4× прогоняет больше шагов за кадр.

## Слоны

- **Профиль** (`herd.ts`) создаётся один раз и хранится в сейве: 11 числовых черт из трёх скрытых факторов (смелость, энергия, дружелюбие) с индивидуальным шумом, возраст, внешность, любимая еда, отношения в стаде. Среди кандидатов берётся самый непохожий на уже выбранных — стадо разнообразно.
- **Выученное**: доверие, покладистость, ожидание ответа на сигналы. Меняются от опыта, на физиологию не влияют.
- **Потребности** (`behavior/needs.ts`): голод, жажда, мочевой пузырь, кишечник, усталость, скука, одиночество, жара, стресс. Стресс стремится к цели, которую задают неудовлетворённые потребности, грязь, теснота и характер.
- **Решение** (`behavior/options.ts`): каждый вариант поведения получает полезность из потребностей, черт и среды. Физиологическая срочность масштабируется выше «хотелок».
- **Исполнение** (`behavior/act.ts`): занятие — состояние автомата с фазами «идти» и «делать», подход по навигационной сетке с полем зазора, поворот корпуса, эффекты в мире.
- **Движок** (`behavior/engine.ts`): полный пузырь или кишечник — всегда, где бы ни стоял; пересмотр плана раз в 1.6–3.2 мин; смена занятия только если новое лучше текущего с запасом (растёт с упрямством); откаты после занятий; встречи и расталкивание тел.
- **Сигналы** (`behavior/signals.ts`): туалет, наружу, внутрь, еда, вода, внимание. Подаёт ли слон сигнал и насколько ясно — выразительность, ожидание ответа, доверие. Ответ (ворота, вода, сено, внимание, зов к стоку) повышает ожидание; игнорирование снижает, и слон справляется сам — например, мочится на подстилку.

## Мир и кипер

- Пол вольеров — клетки 1 м: подстилка, влажность, грязь. Моча мочит подстилку (над стоком — уходит в канализацию), залежавшийся навоз растаптывается в грязь, песок на выгуле сохнет сам.
- Действия кипера — данные (`глагол:цель`), а не замыкания: `availableActions` строит список по контексту, `performAction` проверяет и запускает, работы занимают время.
- Защищённый контакт: дверь кипера в зону открыта, только если в ней (и во всём, что соединено открытыми воротами) нет слонов; ворота не закрываются на слоне и не открываются, пока в вольере тачка.

## Сохранения

Формат `elephant-keeper` v2: заголовок, метаданные, состояние. Проверка структуры, реестр миграций для будущих версий, распознавание сейвов прошлой пиксельной версии (`keeper-sim`) — их можно удалить из меню, загрузить нельзя.
